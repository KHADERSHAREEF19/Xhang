▥ xhang. / v3

A first-time walkthrough

A private voice
inside a sound.

Use the original demo or your own audio, add text or your actual recorded voice, and protect it with a random key. Everything stays on your device.

Start locally

Install Node 20.19 or newer. In VS Code, open the project folder and run: 

npm ci
npm run dev

Open http://localhost:5173. Keep the terminal running. Do not double-click index.html. For an update, overwrite every included replacement file and run npm ci again.

01 / Hide

01

Choose the carrier sound

In Hide, choose Use our original piano-like demo, or upload an MP3, WAV, OGG or M4A. Songs, speech and ambient recordings work. Wait for “ready,” then Continue. MP4 video is not supported.

02

Add text or your voice

Write a message, or choose Voice note and record with your microphone / upload an existing voice recording. Voice limit: 60 seconds / 10 MiB. Uploaded original bytes are not transcoded. Preview locally, then Continue.

03

Copy the generated key

Keep the recommended generated key. Copy it somewhere safe and check the saved-secret confirmation. Alternatively choose a long, independently random passphrase; names like Justin are not accepted. Passphrase guardrails cannot prove entropy. Continue.

04

Pass a rehearsal

Copy the secret before starting. Click Start full rehearsal. After the countdown, paste or type into the secret field, then press Unlock or Enter before playback ends. This immediately stops the carrier and attempts decryption. Do not wait for the song's end. There are no cue times, expected-length hints, or per-letter checks. Retry if needed. Continue after “Rehearsal passed.”

05

Download the file

Click Download encrypted audio. Keep the copied secret separately. The app discards its sender copy after download. Downloaded encrypted files must be shared in their original form.

02 / Unlock

01

Select the downloaded package

Open Unlock and select the encrypted .xhang audio file—not the original demo. Copy the complete private key/passphrase before starting. Real packages never show their secret.

02

Enter, then explicitly submit

Click Start audio & enter secret. After 3–2–1, enter or paste the full secret into the input field. Press Unlock or Enter during playback. Only this explicit submission attempts decryption; no per-keystroke checking. Case matters; spaces count in passphrases. Piano taps are optional lowercase input, not cryptographic pitches.

03

Read or listen privately

Success shows Decryption completed, then your text or the original voice-note player and download button. Voice does not auto-play. Incorrect secrets, tampering, expiry or leaving the tab/window produce the same Nothing unlocked.

One submission, not invulnerability. Starting marks a real file used in this browser, even on failure. Clearing storage, another browser or modified code bypasses the game rule. Encrypted files permit offline guessing; use random secrets. Practice allows unlimited retries. This is an unaudited prototype, not a high-risk secure messenger.

Try public practice first

In Unlock, choose Try the public practice demo. Copy its displayed public key, start, paste and submit. Never use that public key for private messages.

Share without destroying it

Send as a Document / file attachment, not a compressed voice message. Send the secret via a different trusted channel. Re-encoding, trimming or conversion can destroy the appended encrypted block. Test your actual sharing route.

v3 compatibility: old v1/v2 encrypted files must be recreated. This format uses authenticated carrier hashing, AES-256-GCM, generated-key HKDF or fixed-cost Argon2id passphrases. It appends ciphertext; it does not encode secrets into the audible pitches.
